Proof of Concept: Broken Integer Overflow Check in pngdec.c decode_text_to_exif()

Overview:
This PoC crafts a PNG file with a tEXt chunk containing keyword "Raw profile type exif"
and a specially crafted length value that exploits the broken overflow check at line 561.

Target: 32-bit build of FFmpeg (where size_t is 32 bits)
The overflow in 2 * exif_len is most impactful on 32-bit platforms.

PoC for broken integer overflow check in FFmpeg pngdec.c decode_text_to_exif().

The vulnerability is at line 561:

(exif_len & ~SIZE_MAX) is always 0, so the overflow check for 2*exif_len is a no-op.

On 32-bit: exif_len = 2147483656 (0x80000008) causes 2*exif_len to overflow to 16.

import struct
import zlib

def make_png_chunk(chunk_type: bytes, data: bytes) -> bytes:
    """Create a PNG chunk with proper CRC."""
    chunk = chunk_type + data
    crc = zlib.crc32(chunk) & 0xFFFFFFFF
    return struct.pack(">I", len(data)) + chunk + struct.pack(">I", crc)

=== Root Cause Analysis ===

File: libavcodec/pngdec.c
Function: decode_text_to_exif()
Line: 561

Broken code:
    if ((exif_len & ~SIZE_MAX) || end - ptr < 2 * exif_len)
        return AVERROR_INVALIDDATA;

Problem:
- exif_len is size_t
- SIZE_MAX is (size_t)-1, the maximum value for size_t
- ~SIZE_MAX is (size_t)0
- exif_len & 0 is always 0
- The first half of the || is ALWAYS false
- Therefore the overflow check for 2 * exif_len is completely non-functional

Fix:
    if (exif_len > SIZE_MAX / 2 || (ptrdiff_t)(end - ptr) < 0 || (size_t)(end - ptr) < 2 * exif_len)
        return AVERROR_INVALIDDATA;

Secondary issue at line 602:
    if (ptr > end)  // should be: if (ptr >= end)
        return AVERROR_INVALIDDATA;

The off-by-one allows one extra iteration of the hex parsing loop when ptr == end,
potentially leaving a byte partially or fully uninitialized.
